# Прогресс реализации

Простой реестр работ по [продуктовым требованиям](PRODUCT_REQUIREMENTS.md).
Архитектура описывает целевой дизайн, а эта таблица — состояние реализации.

## Как обновлять

- Статусы: **План** → **В работе** → **Частично** → **Готово**; **Блокер** — работа
  остановлена, причина указана в следующем шаге. «Частично» означает, что есть
  работающая часть, но пользовательский результат ещё не достигнут.
  **Не проверено** — состояние ещё не оценено; это не утверждение об отсутствии кода.
- При начале работы укажите исполнителя; при передаче — следующий конкретный шаг.
- «Готово» ставится после проверки всего результата строки. В доказательстве
  укажите тест/команду, коммит или сценарий ручной проверки. Наличие интерфейса,
  миграции или ответа 501 само по себе не означает готовность.
- Обновляйте таблицу вместе с изменением кода. Технические нюансы записывайте в
  [IMPLEMENTATION_NOTES.md](IMPLEMENTATION_NOTES.md), а не в требования.
- Крупную строку можно разделить, когда у её частей появляются отдельные исполнители.
