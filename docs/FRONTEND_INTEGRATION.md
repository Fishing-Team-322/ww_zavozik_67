# Рабочий путь UI → Go API → ML

Изменения `max-back` основаны на `main` (`990f8b5`). Рабочий клиент находится
в `underfront/`; каталог `web/` не является текущим приложением.
Интеграция 1С, её DTO, обработчики источников/worker и миграции в этой работе
не меняются. Настройку и реальные проверки 1С ведёт второй бэкендер.

## Пользовательский путь

Вход → компания → загрузка CSV/XLSX → worker → нормализованные операции →
прогноз ML → график и кассовые разрывы → дополнительный платёж/сценарий.
Регистрация и выбор компании больше не являются локальными заглушками.
SMTP и OAuth требуют внешних настроек; кнопки показываются по конфигурации API.

| Экран | Основные API |
| --- | --- |
| Обзор | `GET /companies/{id}/dashboard` |
| Операции | `GET /companies/{id}/operations`, `/operations/summary`; `PATCH /operations/{id}/category`; `POST /companies/{id}/exports` |
| Прогноз | `GET /companies/{id}/forecast?horizon=30\|60\|90` |
| Сценарий | `POST /companies/{id}/scenarios/preview`, `/scenarios` |
| Разрывы | `GET /companies/{id}/gaps`, `/gaps/{id}`; `POST /gaps/{id}/simulate`, `/actions/{id}/apply` |
| Календарь | `GET /companies/{id}/calendar`; CRUD `/events`, `POST /companies/{id}/events/parse` |
| Загрузка | `POST /companies/{id}/uploads`, `/uploads/{id}/mapping`; preview, jobs, imports, sources |

Все пути имеют префикс `/v1`. Полный контракт — [OpenAPI](../api/openapi.yaml),
полный реестр и доменные ограничения — [BACKEND_API.md](BACKEND_API.md).
Существующие 106 операций сохранены. Dashboard, календарь, summary, upload preview,
ответ о mapping и симуляция разрыва получили конкретные схемы вместо Object.
Симуляция возвращает тот же `Gap` с `snake_case` и датой `YYYY-MM-DD`.

Фронт переводит `in/out` в `income/expense`, `missed` в `overdue` только в адаптере
графика; сохраняет источник, редактируемость и вероятность события. Для истории
и сценария неизвестные значения остаются `null`. Вероятности и суммы вычисляет Go.
Недоступный ML, короткая история и отступление к baseline отображаются явно.

## Быстрый пересчёт

API/worker оборачивают ML в ограниченный кэш: до 16 запросов на процесс, TTL 1 минута.
Ключ включает компанию, всю историю, модель, горизонт, seed и scope. Изменение истории
или модели приводит к новому вызову ML. Дополнительные планы и сценарии применяются
заново к копии общих случайных путей; их изменение не требует повторного ML-вызова.
Ошибки, fallback и отменённые вычисления не кэшируются. Это не кэш итогового баланса:
новый расход виден сразу и не учитывается дважды.

Файлы `ml/artifacts/**/*.txt` должны иметь LF: LightGBM хранит в них байтовые
размеры деревьев. Добавлен `.gitattributes`, чтобы Windows checkout не ломал модель
заменой LF на CRLF. Веса и обучающие данные не менялись.

## Проверка

Тесты API с Postgres проверяют контракт, сохранность, изоляцию доступа, загрузки,
идемпотентность действий и сценарии. `TestLiveMLThroughFinancialAPI` дополнительно
вызывает настоящий Python-сервис с артефактами из репозитория:

```bash
# В backend; сначала запустить Postgres и ML.
TEST_DATABASE_URL='postgres://user:password@localhost:5432/test?sslmode=disable' \
TEST_ML_ADDR=localhost:50051 go test ./internal/httpapi -run TestLiveMLThroughFinancialAPI -count=1 -v
```

Тест использует собственную SQL-схему и синтетическую историю за 120 дней с
нулевыми потоками в выходные. Он проверяет реальную модель без fallback, повторное
использование ML-путей, ровно одно списание дополнительного расхода на каждом
дне прогноза и новый вызов при выборе другой модели. CI поднимает Python и Postgres
для этой проверки. Frontend CI проверяет генерацию типов, тесты клиента/адаптеров,
TypeScript, линтер подключённых компонентов и production build.

В локальном браузере проверены вход, загрузка синтетической CSV-выписки (240
операций, 0 ошибок), обзор, добавление/перенос события, кассовый разрыв,
моделирование переноса и сохранение негативного сценария. Навигация проверена
на узком и широком экране.
Проверка использует отдельную локальную базу; внешние сервисы и данные пользователей
не требуются. Результаты не являются новой оценкой точности ML: для неё остаются
протоколы [ml/reports/quality.md](../ml/reports/quality.md).

Настройка реальных SMTP/OAuth, 1С и других внешних источников, полный UI
администрирования/налогов/договоров и приёмка на выписке команды остаются отдельными
задачами. Дополнительные API доступны по контракту; наличие метода не означает
наличия отдельного законченного экрана для каждой расширенной функции.
