# Детали реализации и подводные камни

Здесь — конкретные ограничения и нюансы кода, а не новые продуктовые требования.
Целевой дизайн — в [ARCHITECTURE.md](ARCHITECTURE.md), состояние работ — в
[PROGRESS.md](PROGRESS.md). Обновляйте заметку при изменении соответствующего поведения;
не дублируйте здесь весь API или инструкции быстрого старта из README.

## Контракты и генерация

- Источники контрактов: `api/openapi.yaml` и `proto/`. Изменения генерируемого кода
  делаются через них и настройки генерации, а не вручную.
- `make gen-api` запускает и генерацию HTTP-кода, и обновление 501-заглушек.
  Обработчик реализуется методом на `httpapi.Server`; зарегистрированный маршрут
  ещё не означает работающий endpoint. Сейчас сервер реализует health и список моделей.
- В `backend/internal/httpapi/oapi.yaml` отключён `embedded-spec`: сервер не использует
  встроенную копию спецификации. Не возвращайте непрозрачный сжатый payload ради
  генерации типов и маршрутов — они генерируются без него.
- `make gen-proto` требует также Python-окружение `ml/.venv`; зависимости и команды
  установки описаны в README и Makefile. После генерации проверьте diff и повторяемость.

## Денежные данные и логи

- В `domain.Operation` сумма — неотрицательная величина, направление хранится отдельно.
  В детерминированной компоненте прогноза сумма уже со знаком. Эти представления
  нельзя смешивать; конечный остаток может быть отрицательным.
- CSV-парсер отклоняет отрицательные суммы операций и нечисловые/бесконечные денежные
  значения, но допускает отрицательный конечный остаток.
- Редакция доменных типов не защищает исходную строку внутри ошибки. Например,
  `strconv.NumError` содержит входное значение: не оборачивайте такую ошибку в логируемую
  диагностику без очистки. Сохраняйте номер строки, поле и причину, а не значение ячейки.

## Прогноз и сценарии

- `forecast.Input.AsOf` — последний день факта; прогноз начинается со следующего дня.
  История для стохастической модели должна исключать потоки, уже учтённые
  детерминированно. При подключении регулярных платежей проверьте отсутствие двойного счёта.
- `Assembler` переходит на fallback при ошибке основной модели. В бэктесте смотрите
  `model_used`, а не только заказанную модель: успешный расчёт может оказаться бейзлайном.
- Go gRPC-клиент принимает до 64 MiB, как и Python-сервис; стандартных 4 MiB недостаточно
  для поддерживаемых крупных ответов. Тест `mlclient_test.go` покрывает 5000 × 90 путей.
- Сценарий не должен менять базовый результат через общие slice: используйте существующее
  клонирование и сохраняйте тест неизменности базы. Сейчас реализован не весь набор сценариев.
- Порог `ingest.MinGapDays = 10` — текущая эвристика пропусков, а не утверждённое продуктовое
  правило. У `safe_to_spend` и разметки разрывов также нужно согласовать смысл параметров
  до пользовательской приёмки; наличие функции не закрывает это решение.

## Выгрузки и эксплуатация

- `encoding/csv.Writer` буферизует вывод. `csvout` проверяет запись, flush и закрытие;
  команды должны завершить вывод до сообщения об успехе. Регрессия покрыта `/dev/full`.
- Сейчас `make backtest` и `make export` пишут **CSV**. Parquet в целевой архитектуре —
  план, не существующий формат выгрузки. Не стройте потребителей в предположении обратного.
- Development Postgres опубликован только на `127.0.0.1:5432`; контейнеры используют
  `postgres:5432`. Это не замена производственной настройке пароля и контроля доступа.
- API должен завершаться с ошибкой при неудачном bind и успешно при штатном SIGTERM.
  Тесты `cmd/api` собирают бинарник и используют локальный порт: нужен Go в PATH.
- `docker compose config` проверяет разрешённую конфигурацию, но не доказывает готовность
  полного стека. Worker и bot пока каркасы, а не работающие очереди и доставка уведомлений.
