# ML-контракт и подключение из Go

Область этой ветки: подготовка обучающих потоков, модели, gRPC, Go-клиенты и проверки. HTTP/import pipeline, база, сценарии и интерфейс остаются у владельцев backend.

## Что фактически подключено

На 24 октября 2026 `backend/cmd/api/main.go` создаёт forecast-клиент из `ML_ADDR`
и передаёт его в HTTP Server. Реализованы health и список моделей. Однако
`GetForecast`/`GetGap` всё ещё наследуют `Unimplemented` и возвращают 501:
успешный `mlcheck` подтверждает gRPC → Go Assembler → risk, но не готовый HTTP-сценарий.
В API/import pipeline нет вызова `DialMLCategorizer`/`Hybrid`; это готовые компоненты
для последующего подключения, а не уже включённая категоризация всех загрузок.

При подключении backend должен передать в HTTP-ответ `model_version`, `warnings`,
`fallback_used`, `flow_scope`, `low_confidence`; текущий generated Forecast DTO
содержит только последнее из этих полей. У финансовых полей DTO сейчас `float32`:
при согласовании API стоит сохранить точность `float64`/`double` внутреннего ML/Go
контракта, не округляя крупные остатки на границе. Generated-файлы здесь не правились.

Экспорт обучающих потоков пока использует фиксированные Go rules. Включение Hybrid
может изменить не только категории, но и исключаемые `own_transfer`/`owner_loan`
и календарные признаки. Перед таким переключением нужны сравнение новых потоков
и отдельная проверка прогноза на development; нельзя считать смену категоризатора
нейтральной для обученного forecast artifact или проверять её подбором по frozen audit.

## Прогноз

`forecast.v1.ForecasterService.Forecast` принимает **непрерывную ежедневную историю**. Приток и отток — конечные неотрицательные числа. Отсутствующий день передаётся с `missing=true` и нулевыми неизвестными величинами; тихий день с достоверным отсутствием операций — `missing=false`. Полностью неизвестная история отклоняется.

`flow_scope=business_without_internal_transfers`: исключены `own_transfer` и `owner_loan`, включены зарплата, налоги, аренда и остальные регулярные платежи. Пустое поле поддерживается для старых клиентов с тем же смыслом. `residual_only` не поддерживается. **Повторно добавлять поверх ML автоматически обнаруженные зарплату/налоги/аренду нельзя**: это двойной учёт. Для остаточной модели потребуется отдельное обучение на данных после удаления регулярных компонент. Известные будущие события можно учитывать только как согласованные дополнительные изменения относительно базового прогноза.

Сервис возвращает пути **потоков**, а не остатков. Go строит остатки от актуального opening balance, затем считает квантили и риски. Дневные квантили потоков нельзя суммировать вместо квантилей накопленных путей.

- Горизонт 1–366 дней, 1–5000 путей, не более 1 млн ячеек, история 1–3650 дней.
- Ненулевой неотрицательный seed обеспечивает повторяемость при тех же данных/артефакте/коде. Seed 0 выбирает случайное зерно.
- `model_version` идентифицирует артефакт и код. `flow_scope`, `warnings`, `fallback_used`, `low_confidence` нужно передавать дальше как метаданные результата.
- У бустинга обученный горизонт 30 дней; более длинный хвост использует naive и сопровождается предупреждением.
- Если за последние 8 недель нет наблюдений, сервис возвращает `FAILED_PRECONDITION`.
  Seasonal naive также отказывает, если после маски календаря не осталось ни одного
  наблюдения для выборки: неизвестные рабочие дни нельзя превращать в нулевые потоки.
  Наблюдаемые нулевые потоки на допустимых днях остаются валидными данными.
  Go Assembler сохраняет `INVALID_ARGUMENT` и `FAILED_PRECONDITION`, не скрывая их
  другим прогнозом. Это касается и явно выбранной необученной модели: нужно
  исправить условие запроса или выбрать `auto`. Fallback при недоступности сервиса сохраняется.
- История с операциями по выходным отключает принудительное обнуление выходных. Календарь РФ не является универсальным правилом для всех источников.
- Короткая история, неполные данные и обнаруженная активность в нерабочие дни требуют внимания к предупреждениям. Нельзя показывать их как доказанную точность.
- gRPC `INVALID_ARGUMENT` — исправить запрос; `FAILED_PRECONDITION` — нет обученного артефакта или наблюдаемой истории. Ошибка зависимости должна включать наблюдаемый fallback, а не незаметно подменять модель.

Go: `forecast.DialML(addr)` и `MLClient.Forecast`. Клиент проверяет размеры, даты, конечность и знак каждого пути, а также известный scope. Текущий `risk.FindGaps` предупреждает по первому дню с P(balance < reserve) ≥ 0.1; вероятность в объекте разрыва — вероятность хотя бы одного пересечения на всём горизонте. Это разные величины. Общая фикстура Go/Python закрепляет это поведение.

## Классификатор

`categorize.v1.CategorizerService.Classify`: до 5000 операций, направление `in`/`out`, конечная неотрицательная сумма, назначение до 8192 символов, имя до 1024. Результаты идут в том же порядке, содержат исходный ID, одну из 20 категорий и confidence. Confidence — оценка модели, а не гарантия.

Go: `categorize.DialMLCategorizer(addr)`; соединение закрывается через `Close`. Клиент разбивает большие наборы на батчи, применяет timeout, проверяет ID/длины/категории. `FailOpen=true` по умолчанию сохраняет работоспособность правил при отказе ML; `OnError` нужен для учёта таких отказов без логирования выписок.

Два способа подключения:

```go
// Прежняя схема: ML получает только пропущенные правилами операции.
chain := categorize.Chain{Steps: []categorize.Categorizer{categorize.DefaultRules, ml}, Threshold: 0.5}

// Opt-in схема: уверенная модель может исправить слишком широкую регулярку.
// Ручные категории сохраняются и не отправляются модели.
hybrid := categorize.Hybrid{Rules: categorize.DefaultRules, ML: ml, MinMLConfidence: 0.8}
```

Hybrid проверен на внутренних отложенных компаниях и регрессионных примерах. Порог 0.8 фиксирован, а не доказан оптимальным для чужих выписок. Высокоуверенные ошибки остаются; спорные категории должны допускать ручную правку. Существующие HTTP-обработчики этой веткой автоматически не переключаются.

## Проверка интеграции

```bash
make gen-proto
make ml-serve
# в другом терминале
cd backend && go run ./cmd/mlcheck -ml 127.0.0.1:50051
```

Проверяется настоящий вызов Go→Python: категоризация, Hybrid, прогноз, версии/scope, одинаковый seed, отказ на неверный scope. ML-specific CI дополнительно собирает и запускает Docker-образ, выполняет Python tests, Go race tests и vet. Не нужны Postgres, Redis, HTTP или внешний LLM.

`auto` дополнительно проверяет доступную историю: при активности по нерабочим дням или полностью отсутствующем одном направлении потока выбирается `seasonal_naive`. Эти режимы не представлены обучающим набором глобальной модели. Ответ содержит фактически выбранное имя, `out_of_domain_naive_fallback`, `fallback_used=true` и `low_confidence=true`. Явный выбор `gbm_global`/`ensemble` остаётся доступен для исследований с предупреждением. Отчёт NN5 содержит исходный результат переноса до этой адаптации; последующие проверки policy считаются регрессионными, поскольку NN5 уже просмотрен.

Дополнительные ограничения входа: величина дневного притока/оттока ≤10^15, модуль суммы категории ≤10^15; в `by_category` принимаются только 20 известных категорий. Идентификатор операции ≤256 символов, ИНН ≤64, суммарный текст одного классификационного батча ≤2 млн символов. Такие ограничения предотвращают разрастание матрицы признаков и переполнение численных расчётов; превышение возвращает `INVALID_ARGUMENT`.

## Отказ Python-сервиса

Go fallback проверяет тот же вход: размеры, непрерывные даты, seed, scope, конечные
неотрицательные потоки и известные категории. Пустая история, полностью неизвестная
история и отсутствие наблюдений в последних 8 неделях не дают нулевой «прогноз»:
возвращается ошибка. Отмена контекста останавливает вычисление. `AsOf` сборщика
должен совпадать с последним днём истории; даты полученных путей проверяются до
накопления остатка.

Встроенный `builtin_seasonal_naive` — аварийная модель без производственного
календаря Python; это явно указано в `warnings` и `model_version`. Если для дня
недели нет ни одного наблюдения, он берёт общий доступный пул, а не выдумывает ноль.
При использовании через Assembler ответ всегда содержит fallback/low_confidence.
Живой `mlcheck` проверяет также накопление остатка, дату/сумму/вероятность разрыва
и тот же сценарий при закрытом соединении с Python.
