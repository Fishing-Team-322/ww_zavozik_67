# Архитектура фронтенда

Проект организован по слоям Feature-Sliced Design. Маршруты Next.js App Router находятся в корневом `app/`; их `page.tsx` и `layout.tsx` собирают интерфейс и не хранят доменную логику. Компоненты отдельного маршрута можно держать рядом с ним в `_ui/`: Next.js исключает такие папки из маршрутизации.

```text
app/                         маршруты и композиция страниц
src/widgets/                 крупные самостоятельные блоки интерфейса
src/features/                пользовательские сценарии и их состояние
src/entities/                доменные типы, модели и правила
src/shared/ui/               UI-кит без бизнес-логики
src/shared/lib/              общие утилиты и форматирование
```

Импорты направлены сверху вниз: `app → widgets → features → entities → shared`. Срезы одного слоя не импортируют друг друга; если несколько срезов используют один код, его нужно перенести на подходящий нижний слой. Внешний код импортирует срез через его корневой `index.ts`; относительные импорты допустимы внутри среза.

`src/entities/payment/model` содержит типы платежей и детерминированный расчёт остатков. `src/features/payment-calendar/model` содержит mock-адаптер для `/test`, а `ui` — переиспользуемый календарь и демо-контейнер. При подключении API mock-адаптер заменяется без переноса визуальных компонентов.

Глобальные CSS-токены и шрифты остаются в `app/`, поскольку их загружает корневой layout Next.js. `src/pages/` не используется: в Next.js это имя может быть воспринято как Pages Router.
