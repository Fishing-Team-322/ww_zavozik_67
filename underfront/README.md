# ПУЛЬС — фронтенд

Next.js 16 / React 19 / TypeScript / Tailwind 4. Глобальный шрифт — локально подключённый Inter Variable (`@fontsource-variable/inter`). Основа интерфейса перенесена из `../old_front` согласно `CODEX_TASK.md` и README того набора.

## Что перенесено

- Все компоненты из `src/components/ui`, включая формы, таблицы, диалоги и чарт-кит.
- `CabinetShell`, `SidebarShell`, раскрывающиеся группы навигации и составные элементы страниц из `src/components/cabinet/shared`.
- Карточки метрик и сигналов из `src/features/cabinet-dashboard/ui`.
- `CashflowForecastChart`, `ScenarioControls`, `RiskCard` из `src/components/finance`.
- Утилиты `src/lib`, `src/shared`; светлая и тёмная тема с зелёным акцентом в `app/globals.css` и `app/puls-accent.css`.

Стили старой платформы (`gov-*`, `tp-*`, карта) не подключены. Код авторизации, ролей, платежей и VTB API не переносился.

## Маршруты

| URL | Раздел | Текущее состояние |
| --- | --- | --- |
| `/` | Обзор | `PulsOverview` с явно помеченными демоданными, прогнозом, календарём и сценариями |
| `/transactions` | Операции | Поле поиска и пустое состояние |
| `/forecast` | Прогноз | График и карточка рисков ожидают расчёт |
| `/scenarios` | Сценарии | Параметры можно менять; расчёт ожидает API |
| `/risks` | Кассовые разрывы | Пустое состояние до расчёта |
| `/calendar` | Календарь платежей | Пустое состояние до загрузки платежей |
| `/sources` | Источники данных | Можно выбрать CSV; файл не отправляется до согласования API |
| `/development/components` | Кнопки и поля | Примеры обновлённых элементов интерфейса |
| `/test` | Каталог компонентов | Интерактивные примеры на изолированных моковых данных |

Главная страница показывает синтетические данные с пометкой «Демо-данные»; остальные рабочие разделы не показывают вымышленные остатки, вероятности или риски. Дополнительные моковые данные используются на `/test` и `/development/components`. У тонкого общего хедера есть линия снизу, у сайдбара — справа. Аватар пользователя находится справа в хедере и открывает информацию о профиле по наведению или нажатию. Основная область без рамки и тени примыкает к сайдбару и правому краю окна, заполняя высоту от хедера до низа экрана. `CabinetShell` находится в корневом layout и сохраняется при переходах между страницами; вверху каждой страницы он показывает breadcrumbs вместо заголовка. `PageLayout` собирает содержимое страницы и необязательные вкладки. Переключение темы находится в сайдбаре и сохраняется в `localStorage`.

## Что нужно от бэкенда

Нужны контракты для источников и загрузки выписки, списка операций, календаря платежей, 30-дневного прогноза, рисков и пересчёта сценария. Для графика ожидается список дней с датой, фактом, базовым и негативным прогнозом, возможными границами и событиями. Оценка вероятности показывается только если её вернул бэкенд. После согласования контрактов можно подключить типизированный клиент, debounce и отмену устаревших запросов сценария.
