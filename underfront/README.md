# ПУЛЬС — фронтенд

Next.js 16 / React 19 / TypeScript / Tailwind 4. Существующие UI-компоненты,
стили и FSD-слои сохранены; правила импортов — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск с API

1. Запустите Postgres, миграции, API, worker и ML по [основной инструкции](../README.md).
2. В этой папке скопируйте `.env.example` в `.env.local`. По умолчанию API работает
   на `http://localhost:8080`, Next — на `http://localhost:3000`.
3. У API задайте `FRONTEND_URL=http://localhost:3000` и
   `PUBLIC_URL=http://localhost:8080`; для локального HTTP — `COOKIE_SECURE=false`.
4. Выполните `npm ci`, затем `npm run dev`.

`BACKEND_ORIGIN` задаёт origin Go API для проксирования `/v1/*` через Next.js.
В корневом Compose он настроен автоматически. Для прямого подключения к API
можно задать `NEXT_PUBLIC_API_URL` при сборке; тогда API должен разрешать CORS
для `FRONTEND_URL`. Секреты в публичные переменные не помещайте.

Создайте аккаунт и компанию, затем загрузите выписку в разделе источников.
Для прогноза нужен остаток на конец дня; короткая или неполная история отмечается
сервером предупреждениями. Worker обязателен для обработки загрузок.

## Подключённые страницы

| URL | Данные и действия |
| --- | --- |
| `/`, `/overview` | Обзор из dashboard API, показатели, график, риски и события |
| `/transactions` | Поиск, категории, фильтры, страницы, исправление категории, XLSX |
| `/forecast` | История и прогноз на 30/60/90 дней, интервалы, безопасная сумма |
| `/scenarios` | Снижение выручки, задержка плана клиента, дополнительный расход; сравнение и сохранение |
| `/risks` | Дата, сумма, вероятность разрыва; причины, моделирование и применение действий |
| `/calendar` | Календарь, источник и статус событий; ручное добавление/правка/удаление; разбор описания с подтверждением |
| `/sources` | CSV/XLSX и подключение 1С:Бухгалтерии 3.0 через опубликованный OData; проверка, синхронизация, отчёты |
| `/login`, `/register` | Вход/регистрация через API; только настроенные OAuth-провайдеры |
| `/forgot-password`, `/reset-password`, `/auth/callback` | Сброс через SMTP, обработка ссылки и OAuth-возврата |
| `/test`, `/development/components` | Отдельные прежние демонстрации UI с локальными данными |

Рабочие страницы не подставляют демонстрационные суммы. Отсутствующий остаток —
`null`, а не ноль. Access token хранится в памяти, refresh — в HttpOnly cookie.
Выбранная компания едина для всех финансовых страниц. Запросы отменяются
при смене раздела/компании; параметры сценария отправляются с задержкой 300 мс.

Типы генерируются из `../api/openapi.yaml` в `src/shared/api/schema.gen.ts`.
Клиент — в `src/shared/api`, преобразование в модели графика — в
`src/entities/forecast`. Для подключения 1С нужны HTTPS URL стандартного OData, учётная запись с правом чтения, ИНН компании и один её 20-значный банковский счёт. Сервер должен иметь доступ к этому URL; хост разрешается администратором через `SOURCE_ALLOWED_HOSTS`. Backend автоматически проверяет публикацию Бухгалтерии 3.0 и находит внутренние ключи по ИНН и номеру счёта. После подключения экран вызывает существующие `test/sync` и показывает результат. Планы счетов доступны, когда они опубликованы в OData; экран источников показывает остаток, оплату и статус. Счёт без подтверждённого срока не ставится в платёжный календарь по дате документа и остаётся вне точечного прогноза.
Облачное состояние, администрирование и остальные дополнительные API не имеют
полных отдельных экранов; реестр API шире этого пользовательского маршрута.

## Проверки

```bash
npm run gen:api
npm test
npm run typecheck
npm run lint:api
npm run build
```

Браузерные проверки: `npm run test:e2e`. Они создают новые тестовые аккаунты и компании на локальном API, поэтому запускать их следует с отдельной E2E-базой. На Windows используется установленный Edge; на Linux сначала выполнить `npx playwright install chromium`. Адреса переопределяются через `E2E_BASE_URL` и `E2E_API_URL`.

Отдельный live smoke включается только при заданных `LIVE_ONEC_URL`, `LIVE_ONEC_INN`, `LIVE_ONEC_ACCOUNT` и использует учебную копию из аудита (15 операций, 7 счетов). Без них тест 1С пропускается. Другие тесты используют синтетические данные; выписка генерируется в памяти. Скриншоты сохраняются в `docs/e2e-screenshots`, диагностические traces — в игнорируемый `test-results/`. Подробности — в `docs/FULL_PLATFORM_E2E_REPORT.md` и `docs/SERVER_DEPLOYMENT.md` из корня проекта.

`lint:api` проверяет подключённые к API компоненты; общий `npm run lint` также
включает старые демонстрационные страницы. Проверки выполняются в CI.
Сквозной сценарий и ограничения — в [FRONTEND_INTEGRATION.md](../docs/FRONTEND_INTEGRATION.md).
