# Учебная 1С: конфигурация и публикация OData

Срез 24.10.2026. Исходная публикация `http://127.0.0.1:8093/codexaccounting/odata/standard.odata/` вернула HTTP 200 для `$metadata` и 22 `EntitySet`. Отдельная публикация клона `/codexobligations/odata/standard.odata/` вернула HTTP 200 и 33 `EntitySet`. Наличие объекта в конфигурации и публикация в OData проверены отдельно.

| Объект | В конфигурации | Исходный OData | OData клона | Проверенные поля/связь |
|---|---|---|---|---|
| `Document_ПоступлениеНаРасчетныйСчет` | Да | Да | Да | `Ref_Key`, `Date`, `Posted`, `Организация_Key`, `СчетОрганизации_Key`, `СуммаДокумента` |
| `Document_СписаниеСРасчетногоСчета` | Да | Да | Да | Те же основные поля; `НеПодтвержденоВыпискойБанка` |
| `Document_ПоступлениеНаРасчетныйСчет_РасшифровкаПлатежа` | Да | Да | Да | `Ref_Key` родителя, `LineNumber`, `СчетНаОплату_Key`, `СуммаПлатежа` |
| `Document_СписаниеСРасчетногоСчета_РасшифровкаПлатежа` | Да | Да | Да | Та же структура ссылки на исходящий счёт |
| `Document_СчетНаОплатуПокупателю` | Да | Нет | Да | `Ref_Key`, `Date`, `Posted`, `DeletionMark`, `DataVersion`, `СуммаДокумента`, `Организация_Key`, `Контрагент_Key`, `ДоговорКонтрагента_Key`, `ВалютаДокумента_Key`; 7 документов, один создан для E2E |
| `Document_СчетНаОплатуПоставщика` | Да | Нет | Да | Аналогичные ключи и сумма; коллекция пустая |
| `Catalog_ДоговорыКонтрагентов` | Да | Нет | Да | `УстановленСрокОплаты`, `СрокОплаты`; 4 договора, у всех срок выключен |
| `Catalog_Валюты` | Да | Нет | Да | `Ref_Key`, код валюты для проверки RUB |

Причина первоначального отсутствия счетов: объекты уже были в типовой конфигурации, но не входили в состав опубликованного стандартного OData. В изолированном клоне обработка `enable-obligations-odata.epf` добавила девять объектов (`odata-setup.result`: `enabled=9`), не изменяя основную базу и конфигурацию. Запросы к новым наборам и фактическое чтение счета с HTTP 200 подтвердили право чтения в учебной среде. Отдельная read-only учётная запись для промышленного пользователя здесь не создавалась.

Исходная файловая база: `%USERPROFILE%\Documents\1C\AccountingDemoTest`; клон: `%USERPROFILE%\Documents\1C\AccountingObligationsE2E`. Сразу после копирования SHA-256 их `1Cv8.1CD` совпадал: `146A1434E39E1774D0DC3182F962ACBC790331FF892A2244E8B2117453CC8014`. Клон опубликован из `C:\ProgramData\Codex1C\AccountingObligationsE2E` на отдельном `/codexobligations`, привязка IIS — только `127.0.0.1:8093`. Действующая копия `/codexaccounting` не заменялась. Для восстановления достаточно прекратить использовать публикацию клона.

Обезличенные ответы: счёт покупателю `Posted=true`, `DeletionMark=false`, `СуммаДокумента=350000`; связанное поступление `Posted=true`, `СуммаДокумента=100000`, строка `СчетНаОплату_Key` указывает на `Ref_Key` счёта. Персональные идентификаторы и исходные документы не коммитятся. В клоне после записи: 15 проведённых банковских фактов (в исходной публикации было 14).

Механизм публикации: [официальная документация 1С](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Integration/Publishing_standard_REST_API_for_your_infobase/?language=en). Учебная версия ограничивает число сеансов и не доказывает готовность к промышленному подключению.
