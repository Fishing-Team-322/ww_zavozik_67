# Маппинг опубликованной учебной 1С

На 24.10.2026 `codexaccounting/odata/standard.odata/$metadata` возвращает 22 коллекции. Реальный локальный config хранится вне Git в `%USERPROFILE%\Documents\1C\ODataSetupLocal\accounting-odata-config.json`.

| Назначение | Коллекция | Поля из настоящего `$metadata` |
|---|---|---|
| Входящий банковский факт | `Document_ПоступлениеНаРасчетныйСчет` | `Ref_Key`, `Number`, `Date`, `Posted`, `Организация_Key`, `СчетОрганизации_Key`, `СуммаДокумента`, `НазначениеПлатежа` |
| Исходящий банковский факт | `Document_СписаниеСРасчетногоСчета` | те же основные поля; также `НеПодтвержденоВыпискойБанка` |
| Связь входящей оплаты со счётом | `Document_ПоступлениеНаРасчетныйСчет_РасшифровкаПлатежа` | `Ref_Key`, `LineNumber`, `СчетНаОплату_Key`, `СуммаПлатежа` |
| Связь исходящей оплаты со счётом | `Document_СписаниеСРасчетногоСчета_РасшифровкаПлатежа` | `Ref_Key`, `LineNumber`, `СчетНаОплату_Key`, `СуммаПлатежа` |
| Контрагенты | `Catalog_Контрагенты` | `Ref_Key`, `ИНН`, `Description` |

У публикации отсутствуют коллекции счетов покупателю/поставщика. Одна ссылка `СчетНаОплату_Key` в банковской строке не даёт сумму счёта, срок и статус. Поэтому нельзя по этим данным объявить остаток счёта или построить живой прогноз. Нужно отдельно опубликовать соответствующие документы в учебной копии 1С, затем повторно прочитать `$metadata` и только после этого настроить `PlanConfig`. Синтетический `testdata/onec_plans_mock.json` не переносить в клиентскую конфигурацию.

Backend позволяет сначала создать источник с `config.base_url` и, если нужны, `username`/`password`, без знания полей 1С. Новый источник получает `status=pending`. `POST /v1/sources/{sourceId}/test` читает service document и `$metadata`, возвращает `discovery`, `missing` и `ready_to_sync` без загрузки финансовых документов. До заполнения `company_account`, `account_map` и `collections` статус `mapping_required`; после проверки полного маппинга — `ok`. `sync` с неполным config отклоняется. Для вложенных путей проверяется наличие корневого поля; содержимое вложенного объекта подтверждается первой синхронизацией. URL разрешает только HTTPS либо HTTP на loopback и должен входить в административный список `SOURCE_ALLOWED_HOSTS`.
