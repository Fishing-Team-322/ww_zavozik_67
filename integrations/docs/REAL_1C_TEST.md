# Проверка установленной учебной 1С — 24.10.2026

## Что подтверждено

- Установлена учебная платформа `1С:Предприятие 8.3.27.1508` в `C:\Program Files (x86)\1cv8t\8.3.27.1508`.
- Создана отдельная файловая база `%USERPROFILE%\Documents\1C\CodexIntegrationTest`, добавленная в список запуска 1С.
- В базу загружена конфигурация из [официального примера 1С](https://1c-dn.com/developer_tools/synchronisation_between_a_mobile_app_and_a_database_server_using_rest_api/) `MobileScanner_Server_REST.cf`. Платформа создала `Catalog.Products` и `Document.Inventory`; её пакетная проверка завершилась сообщением «Ошибок не обнаружено».
- Установлены компоненты IIS и веб-расширение 1С. Публикация `codex1c` создана утилитой `webinstt.exe` с кодом 0. Сайт IIS привязан только к `127.0.0.1:8093`, чтобы учебная база без пароля не оказалась доступна по сети.
- Для живой проверки подготовлена отдельная копия базы `C:\ProgramData\Codex1C\CompatTest`. Для неё задан режим совместимости 8.3.4: по [документации 1С](https://1c-dn.com/download-trial/files/guides/developer_guide.pdf) в таком режиме поддерживаемые объекты доступны в OData без отдельного вызова `SetStandardODataInterfaceContent()`.
- Настоящий локальный запрос к `/odata/standard.odata/` вернул HTTP 200 и коллекции `Catalog_Products`, `Document_Inventory`, `Document_Inventory_Products`. `$metadata` и чтение обеих основных коллекций также вернули HTTP 200.
- В **эту тестовую копию** добавлена одна синтетическая запись товара через OData (HTTP 201). Повторное чтение `Catalog_Products` вернуло эту запись (HTTP 200). Команда Go `inspect-onec` получила названия коллекций и полей от работающей 1С.
- Команда Go `sync-onec` также прочитала запись товара из живой 1С через тот же OData-клиент, который используется для импорта. Получено `parsed=1`, `rejected=1`, `accepted=0` с кодом `not_posted`. Это ожидаемо: товар не является проведённым банковским документом, и адаптер не превратил его в финансовую операцию.

## Что ещё не подтверждено

Первый пример 1С содержал только товары и инвентаризацию. После него установлена официальная учебная «1С:Бухгалтерия предприятия» 3.0.67.54 из скачанного пользователем архива. Созданы отдельная файловая демобаза и её копия для IIS. В OData включены два документа (`ПоступлениеНаРасчетныйСчет`, `СписаниеСРасчетногоСчета`) и три справочника (`Организации`, `БанковскиеСчета`, `Контрагенты`); локальная публикация вернула 22 коллекции с учётом табличных частей. Веб-сайт остался привязан только к `127.0.0.1:8093`.

Для реальных полей `Ref_Key`, `Number`, `Date`, `Posted`, `СуммаДокумента`, `СчетОрганизации_Key`, `НазначениеПлатежа` и `НеПодтвержденоВыпискойБанка` создана настройка вне репозитория: `%USERPROFILE%\Documents\1C\ODataSetupLocal\accounting-odata-config.json`. Команда `sync-onec` прочитала **14 проведённых демоплатежей**: 6 входящих, 8 исходящих, 0 отклонённых. HTTP запуск того же адаптера вернул сначала 14 новых операций, затем 0 новых и 14 повторов; история содержит два batch. Запись в 1С при этих тестах не выполнялась.

В этой конфигурации `Date` используется и как дата документа, и как дата операции: отдельного поля фактического дня отражения выписки в опубликованных объектах не обнаружено. Перед использованием на рабочей базе нужно сверить этот выбор с её правилами проведения и банковской выпиской.

Учебная версия иногда возвращает «достигнуто предельное количество подключений к ИБ» после серии отдельных запросов. Это ограничивает длительные эксперименты на этой локальной базе; сам импорт 14 документов и повторная синхронизация завершились успешно. В демоданных не встретился неподтверждённый банковский документ, поэтому соответствующее отбрасывание подтверждено тестом с локальным HTTP источником, а не живым примером 1С. Поле контрагента в банковском документе опубликовано как ссылка на составной тип; адаптер дополнительно читает справочник `Catalog_Контрагенты`. На живых данных он заполнил 13 имён и 11 ИНН из 14 платежей. Отсутствующие значения не подменяются выдуманными.

Учебная версия [не поддерживает пароли пользователей](https://kb.1ci.com/1C_Enterprise_Platform/Tutorials/Hello__1C/5._Fine-tune_your_application_for_several_platforms/Web_client/). По [правилам 1С](https://v8.1c.ru/priobretenie-i-vnedrenie/otvety-na-tipovye-voprosy-po-litsenzirovaniyu-1s-predpriyatiya-8/) её нельзя применять для работы предприятия. Для проверки будущего подключения клиента нужен тестовый экземпляр обычной 1С с отдельной учётной записью только для чтения и опубликованным OData.

Подключение бухгалтерской 1С самим пользователем через приложение пока не готово: отдельный Go-модуль не связан с backend, а его хранилище работает в памяти.

Повторить чтение описания тестовой 1С на этом компьютере можно из каталога `integrations/`:

```powershell
go run ./cmd/inspect-onec --url 'http://127.0.0.1:8093/codex1c/odata/standard.odata/'
go run ./cmd/sync-onec --config "$env:USERPROFILE\Documents\1C\ODataSetupLocal\accounting-odata-config.json"
```
