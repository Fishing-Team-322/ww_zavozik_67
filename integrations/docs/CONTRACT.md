# ImportBatch v1.0

`POST /v1/import/onec-bank` принимает multipart поля `file`, `company_id`, `company_inn`, `company_account`. ИНН — 10 или 12 цифр, счёт — 20 цифр. `GET /v1/batches/{companyId}` возвращает `{company_id,batches:[ImportBatch...]}` из памяти текущего процесса. Оба маршрута требуют `Authorization: Bearer <INTEGRATIONS_SYNC_TOKEN>`; без него возвращается 401. Токен общий для оператора и пока не обеспечивает права отдельных пользователей или компаний.

`POST /v1/sync/onec-odata` запускает чтение только заранее настроенной 1С. Требует `Authorization: Bearer <INTEGRATIONS_SYNC_TOKEN>` и пустое тело. При отсутствующей настройке возвращает 503, при неверном токене 401, при ошибке 1С 502. URL и учётные данные не принимаются в HTTP запросе. OData использует тот же `ImportBatch`: `source_kind="onec_odata"`, `source_mode="pull"`, а `operation.external_id` содержит идентификатор документа 1С. `GET /v1/providers` сообщает `onecodata: not_configured` или `ready`.

`POST /v1/enrich/dadata-party` принимает JSON `{"inn":"7707083893"}` и тот же Bearer токен. Возвращает отдельный объект `Party` с `inn`, `kpp`, `ogrn`, `name`, `status`, `address`, `source_kind="dadata"`. Сведения не добавляются в `ImportBatch` и не считаются операцией. Возможные статусы: 400 — неверный ИНН/JSON, 401 — токен оператора, 404 — организация не найдена, 502 — ошибка DaData, 503 — ключ не задан.

`ImportBatch` содержит `schema_version="1.0"`, `company_id`, `source_kind="onec_bank_file"`, `source_mode="file"`, случайный `import_id`, `imported_at` в UTC/RFC3339, массивы `operations`, `planned_events`, `issues` и `stats`. Для выписки `planned_events=[]`: неподтверждённые платёжные документы не являются плановыми событиями. `operations` содержит только новые фактические записи данного импорта.

`Operation` содержит стабильный `dedup_key`, `date` (`YYYY-MM-DD`), `amount_kopecks` (`int64`, неотрицательный), `direction` (`in`/`out`), `counterparty_inn`, `counterparty_name`, `purpose`, `source_kind`, `account`, `executed=true`; `balance_eod_kopecks` появляется только при однодневной секции счёта с корректным конечным остатком. Отсутствующие текстовые поля — пустые строки.

`date` — **дата исполнения** из `ДатаСписано` для исходящего и `ДатаПоступило` для входящего платежа. `Дата` — дата документа, используется для идентичности, но не подменяет дату движения денег. Дата хранится как календарный день без часового пояса; при маппинге в backend используется полночь UTC. `direction` вычисляется относительно явно переданного счёта компании; при отсутствии нужного счёта может использоваться ИНН, когда это однозначно. Если оба счёта указаны и ни один не совпадает, документ отклоняется. Противоречие счёта и ИНН также отклоняется. Тип документа не определяет направление.

`dedup_key` — SHA-256 от нормализованных: счёта компании, направления, даты исполнения, даты и номера документа, суммы в копейках, счетов и ИНН сторон, имени контрагента и назначения. Удаляются лишние пробелы, текст приводится к нижнему регистру. Ключ не зависит от времени импорта и `company_id`; хранилище разделяет ключи по компании. Хеш не используется для обезличивания исходных реквизитов.

Для OData `dedup_key` отдельно вычисляется из вида источника, коллекции, `external_id` и счёта. Поэтому повторная синхронизация не создаёт операцию повторно, а изменения уже прочитанного документа пока не применяются.

`stats.parsed` — число секций документа; `accepted` — новые подтверждённые операции в ответе; `duplicates` — повторы внутри файла и ранее импортированные операции компании; `rejected` — документы с issue. `issues[]` содержит только код, номер секции и типовое сообщение, без реквизитов и сумм. Повторный импорт создаёт новый пустой batch в истории, но не добавляет операций.

Ошибки HTTP: 400 — неверные реквизиты, multipart или структура файла; 413 — превышены лимиты; 500 — внутренняя ошибка. Ответ ошибки: `{ "code": "...", "message": "..." }`. Содержимое файла не включается в ошибки или логи.

Для OData `stats.parsed` — число прочитанных JSON записей; непроведённые или некорректные записи попадают в `rejected` и получают типовой `issue`. Следующие страницы принимаются только внутри той же коллекции и на том же адресе. Сырые ответы источника не включаются в ошибки.

Если в конфигурации задан `counterparties`, перед чтением банковских документов адаптер читает указанный справочник 1С и сопоставляет `fields.counterparty_key` с полями `key`, `inn`, `name`. Отсутствующие ссылки оставляют реквизиты пустыми. Справочник ограничен 20 страницами и 4000 записями; превышение возвращает ошибку лимита до импорта документов.

Парсер следует [официальным полям формата 1С](https://v8.1c.ru/tekhnologii/obmen-dannymi-i-integratsiya/standarty-i-formaty/standart-obmena-s-sistemami-klient-banka/formaty-obmena/): `СекцияРасчСчет`, `КонецРасчСчет`, `СекцияДокумент=...`, `КонецДокумента`, `КонецФайла`, `ПлательщикСчет`, `ПолучательСчет`, `ДатаСписано`, `ДатаПоступило`, `Сумма`. Поля могут отсутствовать; без суммы, даты документа, однозначной стороны и даты исполнения запись отклоняется.
