# Будущие счета из 1С: граница живой проверки

24.10.2026 из локальной учебной публикации `codexaccounting/odata/standard.odata/$metadata` получен HTTP 200. В ней доступны проведённые банковские документы и строки расшифровки:

| Коллекция | Подтверждённые поля, нужные для сверки |
|---|---|
| `Document_ПоступлениеНаРасчетныйСчет` | `Ref_Key`, `Posted`, `Организация_Key`, `СуммаДокумента`, `Date` |
| `Document_ПоступлениеНаРасчетныйСчет_РасшифровкаПлатежа` | `Ref_Key`, `LineNumber`, `СчетНаОплату_Key`, `СуммаПлатежа` |
| `Document_СписаниеСРасчетногоСчета` | `Ref_Key`, `Posted`, `НеПодтвержденоВыпискойБанка`, `Организация_Key`, `СуммаДокумента`, `Date` |
| `Document_СписаниеСРасчетногоСчета_РасшифровкаПлатежа` | `Ref_Key`, `LineNumber`, `СчетНаОплату_Key`, `СуммаПлатежа` |

Коллекций счетов в опубликованном `$metadata` **нет**. Поэтому названия документов счета и его поля для этой конфигурации не зафиксированы и конфигурация живого импорта планов не создана. Настройку `PlanConfig` можно заполнить только после публикации нужных объектов и нового `inspect-onec`; синтетический `testdata/onec_plans_mock.json` не является маппингом реальной 1С.

Адаптер `Client.FetchPlans` читает ограниченный полный снимок коллекций без записи в 1С. Для каждой строки оплаты он требует явную ссылку на счёт; если строка не содержит `Posted`, проверяет проведённость и организацию по родительскому банковскому документу. Оплата вычитается из суммы счёта только по этой ссылке. Непривязанный счёт имеет `link_status=unmatched` и не участвует в прогнозе. Неизвестный срок остаётся `due_date=null` и не участвует в прогнозе. Отменённый или полностью оплаченный счёт сохраняется с нулевым остатком. Повторный снимок не создаёт новые события, а изменённые срок, оплата или отмена повышают `version`.

Проверка на синтетическом OData: `go test ./internal/providers/onecodata -run TestPlanned -v`. Для запуска mock вручную задайте `ONEC_ODATA_USERNAME` и `ONEC_ODATA_PASSWORD`, запустите `go run ./cmd/mock-onec`, затем сервер Hub с `ONEC_PLAN_CONFIG=./testdata/onec_plans_mock.json` и `INTEGRATIONS_SYNC_TOKEN`. Вызовите `POST /v1/sync/onec-plans` дважды и `GET /v1/planned-events/demo-company`. Ответы имеют `data_mode=mock`.
