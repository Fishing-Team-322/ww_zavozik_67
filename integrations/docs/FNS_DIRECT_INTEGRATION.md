# Прямая интеграция ФНС

## Возможности

- `POST /v1/fns/egrul/import`, `/egrip/import`: загруженная пользователем PDF-выписка с текстовым слоем, до 32 МиБ. Скан без текстового слоя отклоняется; OCR не выполняется.
- `POST /v1/fns/xml/import`: ЕГРЮЛ/ЕГРИП XML или ZIP до 128 МиБ. Архив проверяется на число и размер файлов, пути и коэффициент распаковки. Разбор идет потоково, без извлечения на диск; сам upload временно хранится в `/tmp`.
- `GET /v1/fns/counterparties/{inn}` и `/history`: текущая запись и последние 100 версий в рамках одной компании. Обновления идут по ОГРН/ОГРНИП и дате состояния; повторный файл не создает новую версию.
- `GET /v1/counterparty-intelligence/{inn}`: профиль, происхождение полей, конфликты, датированные риск-сигналы. ФНС имеет приоритет для подтверждаемых им полей. DaData необязательна.
- `POST /v1/fns/opendata/sync`, `GET /status`: проверка публичной страницы ФНС и импорт только нового набора задолженности. Последний удачный снимок и история запусков хранятся в PostgreSQL.

Все маршруты используют операторский Bearer token. Загрузка также требует `company_id`, равный `INTEGRATIONS_COMPANY_ID`. Публичных пользовательских аккаунтов в Hub пока нет; backend позже должен сам проверять связь пользователя с компанией. Доступа по произвольному `company_id` нет.

## Настройка

В `.env` для Docker или окружении процесса установите `DATABASE_URL`, `INTEGRATIONS_SYNC_TOKEN`, `INTEGRATIONS_COMPANY_ID`, `FNS_DEBT_INNS=ИНН1,ИНН2` и при необходимости `FNS_CHECK_INTERVAL=24h` (минимум 6 часов). Автоматическая проверка запускается после интервала; ручная доступна сразу. Повтор неудачной проверки не чаще чем раз в 6 часов. Одновременный запуск для компании блокируется advisory lock PostgreSQL.

CLI: `go run ./cmd/import-fns-registry --file extract.pdf --company demo-company`, аналогично `.xml` или `.zip`; `go run ./cmd/sync-fns --company demo-company --inns 9723161623`. `DATABASE_URL` передается через окружение, не аргументом команды. API принимает multipart `company_id` и `file`.

Реестровая выписка сама по себе не создаёт денежную операцию или плановый платеж. Сигнал задолженности указывает датированный публичный срез, а не текущий баланс ЕНС. Профиль `VERIFIED` означает структурно корректный импорт сведений с происхождением ФНС; **не означает проверки УКЭП или подлинности загруженного файла**. Для принятия юридически значимого решения необходима проверка исходного документа и подписи.

## Ограничения

PDF-парсер поддерживает текстовые выписки с распознаваемыми полями; разные шаблоны ФНС могут потребовать дополнительных шаблонов. XML-парсер использует опубликованные элементы актуальных XSD, но полная XSD-валидация и автоматический FTP-клиент отсутствуют. IP-персональные данные нельзя помещать в фикстуры или журналы. Отсутствие контрагента в загруженном фрагменте XML означает только `NOT_FOUND` в локальном хранилище, а не отсутствие в государственном реестре.
