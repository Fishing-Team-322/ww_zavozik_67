# Локальная PostgreSQL для Integration Hub

Из `integrations/`: скопировать `.env.example` в локальный `.env`, заполнить два **разных случайных** значения `INTEGRATIONS_SYNC_TOKEN` и `INTEGRATIONS_DB_PASSWORD`, запустить `docker compose up --build -d`. `.env` игнорируется Git. Контейнеры слушают только `127.0.0.1:8091` (Hub) и `127.0.0.1:5543` (PostgreSQL). Данные лежат в именованном томе `integrations_pgdata`; `docker compose restart hub` не удаляет их. Миграции выполняются при старте сервиса. `GET /healthz` проверяет процесс, `GET /readyz` — соединение с БД.

Таблицы разделены по `company_id`: банковские операции, планы, батчи, финансовые строки маркетплейсов, профили контрагентов, риск-сигналы, конфигурации подключений, запуски синхронизации. Сейчас записываются операции, планы, батчи, строки WB/Ozon, профили DaData, датированные сигналы ФНС и запуски синхронизации; подключения пока имеют только схему. Факт, план и строка маркетплейса имеют отдельные ключи и версии. Повторный импорт не создаёт дубли, исправление документа обновляет строку. Запросы из HTTP API ограничены `INTEGRATIONS_COMPANY_ID` (по умолчанию `demo-company`) и операторским токеном. Это локальная модель одного арендатора, не система пользовательских аккаунтов.

`ONEC_SYNC_INTERVAL` при заданной конфигурации запускает независимую периодическую синхронизацию фактов и планов 1С. Ошибка одного источника не останавливает другой; есть таймаут, ограниченный backoff, небольшой jitter и отмена при остановке процесса. `/v1/sync-runs/{companyId}` показывает коды результата. WB/Ozon запускаются вручную через защищённые `/v1/sync/*-finance` с периодом дат и токенами из локального окружения. Для маркетплейсов и ФНС фоновое расписание, конфигурации/курсоры и ротация секретов ещё не подключены. URL 1С пока задаёт только оператор через локальный файл; при реализации пользовательского ввода URL потребуется отдельная проверка адреса и DNS против SSRF.

Проверка 24.10.2026: `docker compose up --build -d`, `POST /v1/import/csv` с демосчётом 350000.00 ₽ → версия 1, повтор → `duplicates=1`, `GET` другой компании → HTTP 403, `docker compose restart hub` → тот же счёт, сумма 35000000 копеек, версия 1. `TEST_DATABASE_URL` включает тест `TestPostgresDurabilityAndCorrection` (запись, закрытие/повторное открытие, исправление факта и плана до версии 2, изоляция компании).
